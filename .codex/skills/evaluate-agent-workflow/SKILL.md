# Evaluate Agent Workflow

루트 [AGENTS.md](../../../AGENTS.md) 규칙을 전제로 사용한다.

## 목적

- 지침을 많이 쓰는 대신, 필요한 제약과 라우팅만 남긴다.
- 지침 변경이 실제 작업 품질·재작업·검증 범위에 미친 영향을 같은 과제로 비교한다.
- 한 번에 한 묶음만 변경해 원인과 결과를 구분한다.

## 대표 작업 세트

변경 성격에 맞는 과제를 최소 세 개 선택한다.

1. 알람 일정 또는 시간대 계산 변경
2. FCM·Google Places·결제·AdMob 같은 외부 연동의 오류 처리 변경
3. 인증·인가 또는 민감 정보 로깅 변경
4. Flyway migration을 포함한 API·도메인 변경
5. 기존 동작을 유지하는 국소 리팩터링

각 과제는 기존 테스트 또는 재현 절차와 완료 기준을 함께 기록한다. 평가를 위해 운영 데이터나 secret을 사용하지 않는다.

## 비교 방법

1. 기준 지침과 변경 지침에서 같은 과제를 실행한다.
2. 지침, 예시, 도구, 문서 라우팅 중 한 묶음만 바꾼다.
3. 각 실행에서 아래 항목을 기록한다.
   - 완료 기준 충족 여부와 관련 테스트 결과
   - 발견·수정된 회귀 또는 리뷰 지적 수
   - 불필요한 문서 열람, 도구 호출, 승인 요청 수
   - 작업 시간 또는 모델 비용을 측정할 수 있으면 그 값
4. 품질 저하 없이 재작업·불필요한 탐색이 줄어든 경우에만 변경을 유지한다.

## 기록 형식

```markdown
## {지침 변경 이름}

### 변경 묶음
- 제거·추가·이동한 지침:

### 대표 작업 결과
| 작업 | 완료 기준/테스트 | 기준 결과 | 변경 결과 | 유지 여부 |
| --- | --- | --- | --- | --- |

### 결론
- 품질 영향:
- 비용 또는 시간 영향:
- 다음에 검증할 가설:
```

결과는 작업 이력 또는 PR 설명에 남긴다. 공개 문서에는 secret, 개인정보, 운영 로그 원문을 기록하지 않는다.
