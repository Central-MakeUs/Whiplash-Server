# Commit Helper

루트 [AGENTS.md](../../../AGENTS.md) 규칙을 전제로 사용한다.

## 목적

- staged 변경 내용을 요약한다.
- 커밋 타입을 분류한다.
- 프로젝트 포맷에 맞는 커밋 메시지를 만든다.

## 작업 순서

1. `git diff --staged`로 staged 변경을 확인한다.
2. staged 파일이 없으면 `git status`로 상태를 확인한다.
3. 변경 의도를 파악한다.
4. 적절한 Type과 제목을 제안한다.
5. 필요하면 본문까지 포함한 커밋 메시지 초안을 만든다.

## 커밋 메시지 규칙

기본 형식:

```text
[#이슈번호] :Emoji: Type: 제목
```

필요하면 아래처럼 본문을 확장할 수 있다.

```text
[#이슈번호] :Emoji: Type: 제목

- 변경 파일 또는 기능 단위 요약
- 핵심 변경 사항 요약
```

## Type / Emoji

- `Feature` / `✨`: 새로운 기능 추가
- `Fix` / `🐛`: 버그 수정
- `Docs` / `📝`: 문서 수정
- `Style` / `🎨`: 포맷팅 위주 변경
- `Refactor` / `♻️`: 리팩토링
- `Test` / `✅`: 테스트 추가 또는 수정
- `Chore` / `🔧`: 빌드, 설정, 기타 유지보수

## 제목 규칙

- 50자 이하
- 마침표 없음
- 변경 의도가 바로 드러나게 작성

## 주의사항

- 커밋은 사용자 요청 또는 확인 없이 임의로 진행하지 않는다.
- staged 범위와 메시지 범위가 맞는지 먼저 확인한다.
- 브랜치명에 이슈 번호 규칙이 있으면 참고하되, 불명확하면 추정이라고 명시한다.
